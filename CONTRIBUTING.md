# Contributing

Thanks for helping. This is a prototype, so short issues and small pull requests work best.

## Issues

- Bugs, ideas and build reports each have a template under "New issue".
- Photos of your build are very welcome; remove location data from them first.
- Security problems in the firmware go through a private report, not a public issue: see [SECURITY.md](SECURITY.md).

## Pull requests

- Keep each pull request to one topic and describe what you actually tested (printed, flashed, or only regenerated).
- Update `CHANGELOG.md`: until the public launch, the pre-launch section that describes the current state.
- CI checks that every committed mesh is watertight (and regenerates the parts when the CAD scripts change), builds the site, lints the MicroPython firmware with ruff and runs `reuse lint`.

## Commits, branches and releases

- Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/): `feat:`, `fix:`, `docs:`, `refactor:`, `chore:`, `build:`, with an optional scope, for example `feat(firmware): ...`.
- `main` is always deployable. Work on a short-lived feature branch (`feature/<topic>`) and merge it through a pull request.
- Releases follow [Semantic Versioning](https://semver.org/), with one tag per version line (`hw-v…`, `case-v…`, `fw-v…`, `product-v…`; see [VERSIONS.md](VERSIONS.md)). On each release, bump the line's version file and update `CHANGELOG.md`. Until the public launch the repository keeps only the latest version of everything; earlier iterations live in the git history.

## How parts are regenerated

Every part is generated by the Python scripts in `hardware/cad/`, so change the scripts rather than editing meshes by hand.

```
pip install trimesh manifold3d shapely mapbox_earcut rtree numpy scipy networkx lxml matplotlib fast_simplification
python hardware/cad/build_v64.py
python hardware/cad/check_meshes.py hardware --skip 'cad/build/*'
python hardware/cad/check_meshes.py hardware/module/case-1.0
```

Commit the regenerated files in `hardware/assembly/`, `hardware/template/`, `hardware/cad/v64.json`, `hardware/cad/check_v64.png` and `hardware/module/case-1.0/` together with the script change, then rebuild the print package with `hardware/plates/tools/run_all.sh` (it needs the OrcaSlicer command line). See [hardware/README.md](hardware/README.md).

The website in `site/` is plain HTML, CSS and JavaScript. Preview it with `python site/build.py` and `python -m http.server -d site/_build`.

## Conventions

- Units: millimetres.
- MicroPython firmware: pins and calibration values live only in `firmware/micropython/src/config.py`; keep `ruff check` clean for new code (see [firmware/micropython/README.md](firmware/micropython/README.md)).
- Frame: Z-up, with X=Y=0 on the shaft axis and Z=0 at the underside of the bowl base; parts are modelled at their assembled position (see [hardware/README.md](hardware/README.md)).
- Part names are Italian and kept as they are, for example `disco` (disc), `chiocciola` (bowl), `albero` (shaft), `mozzo` (hub), `scatola` (servo bay), `fondello` (cap), `guscio` (shell), `scivolo` (chute) and `test_scanalato` (spline test).
